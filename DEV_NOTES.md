# Design decisions

- Independent implementation; no source copied from reference repositories. HDLconv is GPL-3.0-or-later; hdlConvertor is MIT. Reference clones are read-only and excluded from distribution.
- Studied HDLconv core.py, vhdl2vlog.py, ghdl template and tests/run.sh: separate argument parsing, file validation, conversion and diagnostics. No Docker or synthesis backend dependency.
- Studied hdlConvertor processParser, typeDeclarationParser, exprParser, statementParser and hdlAst declarations: use source-located nodes and recursive structural parsing. Its Python visitors/generators live in the separate hdlConvertorAst dependency; do not vendor that dependency.
- Tokenizer preserves source offsets and line numbers. Parser handles balanced parentheses and recursive statements. Expression translation uses operator precedence, never a sequence of global substitutions.
- VHDL names are case insensitive; symbols resolve to declaration spelling. SV reserved names require escaping.
- Ranges store left/right/direction, including nonzero and descending bounds. Unpacked arrays are distinct from packed vectors. Whole array copies always expand to loops; only identical range tuples can share a loop.
- Process edge recognition is deliberately conservative. Signal assignments use nonblocking in clocked processes and blocking in combinational processes; variables always use blocking.
- Unsupported constructs produce diagnostics and source comments. Warning output is a review artifact, not a claim of equivalence. Malformed input must not replace an existing output.
- GUI and CLI call the same converter; no GUI parsing logic. Standard library only in core.
- Release packaging: PyInstaller onefile/console with hide-early (only its owned console), so Explorer launch opens GUI while terminal launches keep CLI output. Frozen no-argument entry defaults to GUI; source CLI behavior remains unchanged. Custom hook includes only win-x64/Tcl 8 tkdnd, omitting other wheel platforms and link-time .lib. Optional networking/OpenSSL, compression and decimal backends are excluded after isolated EXE regression; do not add features using them without updating build exclusions. No UPX or system Python modification. Third-party notices are embedded and available via --licenses.
- Module/interface identifiers are canonical lowercase, so named maps match across independent conversions. Internal symbols retain declaration spelling; SV keywords are escaped.
- numeric_std arithmetic carries small local (kind, width) metadata. Explicit size casts preserve intermediate vector overflow even inside to_integer. Signed resize shrinking retains the source sign bit; scalar multiplication converts the scalar to vector width. VHDL negative sll/srl shifts reverse direction. Integer mod adjusts remainder sign without same-sign addition overflow.
- Unsupported clocks do not fall through to always_comb. Combinational read-after-write signals are conservatively flagged because blocking assignment changes delta-cycle behavior.
- Warning output is allowed by default for review, but --strict blocks any write. Errors never replace existing output. Batch destination collisions are errors.
- Declaration initialization is not a universal hardware driver. drivers.py conservatively identifies whole signals definitely assigned by direct concurrent assignment, with-select (others coverage), or edge-free processes with complete paths. Proven redundant initializers are silently omitted because generated removal comments are unwanted product noise. Partial writes, incomplete branches, feedback, loops/generate and instance binding preserve initialization.
- Process variables are explicitly static to preserve VHDL process lifetime. Their initializer is silently omitted only when control-flow analysis finds no possible read before a whole `:=` assignment; branch intersections and zero-trip loops are conservative. Function-local variables retain automatic function lifetime.
- Source decoding is centralized in `hdlconvert.encoding`: UTF-8/BOM first, then strict GBK (which includes GB2312). File output defaults to GB2312 and supports explicit GBK/UTF-8 selection in both CLI and GUI.
- Initialization-policy diagnostics stay in CLI/GUI logs but are not inserted into generated HDL. Other unsupported-construct source comments remain review artifacts as required by the fail-closed policy.
- Frozen GUI calls `FreeConsole` only when the console process list proves the console belongs solely to this process. It never detaches from a shared parent terminal used for CLI.
- Gmail notifications are concise and sent only for important feature completion or observed usage exhaustion. Always persist WORK_STATE.md and WORK_STATUS.md first; mail failure must not block development.
- After local development and EXE packaging, publishing and GitHub upload require explicit user permission. A local checkpoint commit is allowed; never push, tag, or create/update a Release before that approval.
- Reference snapshots: HDLconv 3aeb734bb503a75703fa8b7432caf80e34352ce1; hdlConvertor 03c081a307850dc3c438df36592fc67b1ef6cfc0. Test external examples in build/ only; do not redistribute reference source.
- Version 2 keeps the mature VHDL-to-SystemVerilog generator for its broader VHDL subset. New VHDL-to-Verilog paths map the VHDL structure directly into `hdl.ir`; Verilog and SystemVerilog share one balanced-token parser and target-aware generators. There are no six independent converters.
- The neutral IR stores expressions structurally. Verilog/SV precedence, packed ranges, casts, concatenation, repetition, process scheduling and instance associations are parsed before generation. Generator code must reject missing type/width evidence instead of guessing.
- Verilog blocking process assignments become VHDL process variables, seeded from signals and committed at process exit, so reads after writes retain procedural ordering. Nonblocking assignments remain signals. Mixed scheduling and multiple process ownership fail closed.
- VHDL declaration initialization uses explicit `SAFE_REMOVE`, `PRESERVE`, and `UNCERTAIN` states. Reset assignments are ordinary statements and never participate in initializer removal. Width checks evaluate simple generic/constant expressions; invalid widths are diagnosed and not truncated silently.
- GUI version 2 is a single-document Windows 10 style editor. It calls `hdl.api.convert_text`; CLI calls `hdl.api.convert_file`. Syntax highlighting is visual only and never feeds the parser.
